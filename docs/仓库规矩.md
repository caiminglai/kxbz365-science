## 1. 一个东西只有一个名字

| 项 | 本站唯一的叫法 | 现量出处 |
|----|----------------|----------|
| compose 服务名 | `twym` | `compose/docker-compose.yml:46` |
| 容器名（本机与服务器**同名**） | `twym-local` | 同文件 `:50`（`container_name` 写死，不是模板生成的） |
| 宿主端口 | `127.0.0.1:3000` | 同文件 `:55` |
| 镜像 | `www-twym:latest` | compose 顶层 `name: www` 决定前缀 |
| 服务器仓库路径 | `/var/www/1.my-first-website` | 同文件 `:48` 的 `context: ../1.my-first-website` 是相对编排仓库写的 |
| 域名 | `kxbz365.cn` + `www.kxbz365.cn` | `compose/caddy/Caddyfile:22`，回源 `reverse_proxy twym:3000`（`:24`） |
| 主库 | `data/同物异名.db` | 仓库工作区，见 §3 |
| 数据卷 | **本站没有命名卷** | compose 的 `twym` 块只有两条 `volumes`（`:57`、`:58`），没有 `postgres`、没有 `pgdata` |

三条硬规矩：

1. **只绑 `127.0.0.1`。** Caddy 走容器网按服务名回源，不经宿主机端口；绑 `0.0.0.0` 等于在 HTTPS 之外再开一个裸后端入口。
2. **服务器上的容器名也带 `-local` 后缀。** 这名字看着别扭，但它是写死在 compose 里的，两台机器一字不差 ⇒ 编排仓库那两个工具（漂移哨兵、备份脚本）不需要任何环境变量覆盖就能在两机跑同一条命令。别"顺手改成" `twym-prod`。
3. **顶层 `name: www` 不许删。** 它是项目名，容器内网络、镜像名前缀、命名卷名都从它派生。改了等于换一套资源，老容器不会自动消失。

## 3. 🔴 本站最承重的一条：Git 跟踪的那三本库，就是正在跑的库

站2 的坑是 `NODE_ENV`（见它的 `docs/仓库规矩.md` §3）。**本站的坑在这里。** 这条不是"建议"，是量出来的因果链：

| # | 证据 | 现量 |
|---|------|------|
| ① | compose 把仓库里的 `data/` **整目录**挂进容器 | `docker-compose.yml:57` `../1.my-first-website/data:/data` |
| ② | 这个挂载是**可写**的 | 容器内 `/proc/self/mountinfo`：`... /website/1.my-first-website/data /data rw,noatime`（`rw`） |
| ③ | 容器里进程的工作目录是 `/app` | `docker exec twym-local sh -c 'readlink /proc/1/cwd'` → `/app` |
| ④ | 库路径来自仓根 `.env` 第 13 行 `DB_PATH=../data/同物异名.db`（**相对 CWD**） | `/app` + `../data` = `/data/同物异名.db` |
| ⑤ | 就算没有 `DB_PATH`，代码默认值也落在同一处 | `backend/db/入口.js:27` `path.join(__dirname, "..", "..", "data", "同物异名.db")`，容器内 `__dirname=/app/db` ⇒ 还是 `/data/…` |
| ⑥ | 容器里看到的文件就是仓库工作区那一个 | 容器内 `ls -l /data` 的 `同物异名.db` = **1,540,096 字节**，与本机 `data/同物异名.db` 同字节同 mtime |

⇒ **`/data` 不是副本，是仓库工作区本身。** 三条后果，都是这一轮就会踩的：

1. **在容器跑着的时候 `git pull` 或 `git checkout -- data/xxx.db`，就是当场替换一个正被打开的库文件。** 本站的库会被应用写（管理后台的备份接口、社区协作的免鉴权写入路径在代码里都存在），所以这不是理论风险。
2. **后端一写库，工作区立刻脏。** 三本 `-wal`/`-shm` 被 `.gitignore:64-66` 挡住，所以真会亮出来的脏是 `M data/同物异名.db` 这种。看到 `M` 的含义是"这台机器写过"，先量再决定搬回还是覆盖，**不要拿 `checkout` 清脏来"解决" pull 被挡**——那等于删掉那一侧的写入。
3. **提交进 Git 的那一份必须是 WAL 已清空的。** 本轮实测三本 `-wal` 都是 0 字节（可以提交）；三本 `-shm` 各 32,768 字节、时间戳是今天（容器在跑就会动它），但它不进 Git，不构成脏，也不用管。

判据（哪一份是权威、为什么三本都进 Git、`git rm --cached` 的禁令、纳管的四条前提）**已经写在 `docs/文档清单总览.md` §二 与 `docs/项目总览.md` 的「数据库现状」段**，本文只指过去，不复制第二份。跨机怎么量漂移：编排仓库 `compose/tools/db-drift-sentinel.sh`（pull 前必跑，口径全文在 `compose/CONVENTIONS.md` §4）。

顺带一条本站与站2 的对照，别把两边的账互抄：站2 的库在 PG 命名卷里，**仓库里没有库文件**，所以那套 SQLite 哨兵对站2 一个字都不适用；反过来，站2 的"每日 `pg_dump` 备份"也不是本站的回退通道。**本站的回退只有 Git 里那三本 `.db`**（`/root/db-backup-*` 与本机 `files/` 下的库副本 2026-09-26 已清空，每日备份脚本按判据不背站1 词库——理由写在 `compose/CONVENTIONS.md` §10 那条备份记录里）。

## 6. 换行符

尺子（三站同一条，可直接粘）：

```bash
git ls-files --eol | awk '{print $1}' | sort | uniq -c
```

2026-10-25 本站现量：**415 `i/lf` + 9 `i/-text` = 424**，`i/crlf` 与 `i/mixed` 都是 0。编排仓库 §10 第一条那句"站1 一直是 0、不需要 renormalize 提交"到今天仍成立。

`.gitattributes` 共 174 行，两处关键：`:15` `* text=auto eol=lf`；`:96-99` 数据库四个后缀（`*.db`／`*.db-shm`／`*.db-wal``*.db-journal`）标 `binary`。**那三行白名单加上这四行 binary 是同一件事的两半**——只有 binary 命中，`git add` 才不会把库文件字节改掉；少了它，`* text=auto` 会重写二进制，库直接废掉，而且 `git status` 看起来完全正常。

那 9 个 `i/-text`（被当二进制的文件）值得点名，其中 4 个是 `.txt`：

```
app/public/alipay.jpg   app/public/wechat-pay.jpg
data/同物异名.db        data/学科词库.db          data/语义词典.db
docs/原始素材/7.控制论与科学方法论_目录及跨学科串讲.txt
docs/原始素材/8.概念抗体_终身防忽悠方法论.txt
docs/原始素材/9.认知防忽悠手册_全球整合版.txt
docs/原始素材/同物异名.jpg
```

后果：那 4 个 txt 在 `git diff` 里只显示 `Binary files differ`，看不到内容差。要看差异得 `git cat-file blob HEAD:<路径>` 自己比。

还有一条跨机账：本机 Windows 工作区带 CRLF 的文件，仓库里其实是 LF（被 `text=auto` 掩盖）。所以**本机重建出来的产物字节数不能和公网比**，跨机只比 `git cat-file` 取回的 blob 的 md5。

## 8. 路由挂载与限流闸

本站后端是 Express，接口前缀写死 `/api/v1`（没有 `API_PREFIX` 环境变量这回事，那是站2 的）。挂载全在 `backend/server.js`：公开段 `:86-99`（14 条）+ 着陆页与 SEO 两条 `:112-113`（`/t`、`/sitemap.xml`+`/robots.txt`，**必须早于** `express.static` 与 SPA 兜底）+ 管理段 `:121-127`（7 条，`/api/v1/admin` 前缀）。

**顺序的两条规矩：**

1. 具体 admin 子路由（`:121-126`）必须早于 `:127` 那条通用 `/api/v1/admin`（它内部 `router.use(adminAuth)` 在 `routes/管理.js:35`）——`server.js:124` 的注释已经在说这件事：`concept-antibodies` 管理页签须早于通用 admin 路由。
2. SPA 兜底永远在最后。判"路由挂上没挂上"别看状态码：兜底会把没挂上的路径伪装成 200 首页，**判据是 Content-Type + 字节数**。

限流：**5 个调用点，两把不同的封禁时长**（现量 2026-10-25）：

| 闸 | 额度 | 超了封多久 | 挂在哪 |
|----|------|-----------|--------|
| 全局 `rateLimiter` | 1,000 次/分 | **1 分钟** | `server.js:48`，常量 `middleware/安全.js:13-15` |
| `searchRateLimiter` | 600 次/分 | 10 分钟 | `server.js:84`（只挡 `/api/v1/terms/search`） |
| `aiRateLimiter` | 10 次/分 | 10 分钟 | `server.js:102-103`（就地 `createRateLimiter(10,…)` 再挂 `/api/v1/ai`） |
| `adminRateLimiter` | 300 次/分 | 10 分钟 | `server.js:119` |
| `suggestionRateLimiter` | 10 次/分 | 10 分钟 | 定义 `安全.js:109`，挂载 `routes/社区协作.js:62`（`POST /suggestions`） |

`createRateLimiter` 的封禁 10 分钟在 `安全.js:67`（`blockDuration`），全局那把是 `安全.js:15` 的 1 分钟。规矩：**新增匿名写入口必须单独挂一把 `createRateLimiter`，不能只靠全局那把**——`安全.js:107-108` 的注释就是这条的理由：每来一次就往库里插一行的端点，用搜索那档 600/分 等于允许一个人一分钟造 600 条待审核垃圾。

取真实访客 IP：`server.js:33` `app.set("trust proxy", 1)`（只信任 Caddy 一跳）。**别删**，删了全网访客被算成 Caddy 一个地址共用 1,000 次/分，超了还把这一个地址拉黑 1 分钟＝一个人把所有人关在门外。

行号会漂，符号不会。判"挂没挂"用这条，别抄上面的号：

```bash
grep -rn "RateLimiter\|rateLimiter\|trust proxy" backend/server.js backend/middleware/安全.js backend/routes/*.js
```

## 9. 提交写法

最近 60 笔现量：55 笔带 `feat|fix|docs|chore|style|refactor` 这类前缀，**20 笔 scope 写成 `(站1)`**。本站 commit 有两种合法长相，各自成立：

- 单独提交本站某处改动 ⇒ scope 用**模块名**：`fix(backend): …`、`fix(社区协作): …`、`chore(前端): …`、`docs(数据口径): …`
- 一轮同时推三站 ⇒ scope 用 `(站1)`，好在 GitHub 上一眼认出这是"那一轮"的一笔

**中文 commit message 一律走 `-F` 文件，不要用 `-m` 或 heredoc**：本机 Git Bash 把中文塞进 argv 会走 GBK，消息里再出现 `//` 开头的串会被当 UNC 路径，两种都是提交成功、内容已废。文件路径用 ASCII，例：

```bash
git -C /e/website/1.my-first-website commit -F /c/Users/Lcm/AppData/Local/Temp/s1-msg.txt
```

**message 里不出现口令、Token、真人资料内容**；要提密钥只写"存在／长度"这种定性说法。
