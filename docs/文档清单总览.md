## 二、数据库

三个 SQLite 库均在 `data/`，是站点数据的唯一真相源，**且由 Git 跟踪**（`.gitignore:76-78` 三行精确白名单 `!data/同物异名.db`／`!data/学科词库.db`／`!data/语义词典.db`，`.db-wal`/`.db-shm` 仍忽略）。2026-09-25 当天反转过一次：上午定"库不进 Git、待 `git rm --cached` 摘除"，当晚按"唯一人工写入源在本机"这条判据改回纳管，**那句摘除指令已作废**。🔴 **不要对这三本执行 `git rm --cached`，也不要删那三行白名单**——本机 `files/` 下的库副本与服务器 `/root/db-backup-*` 已于 2026-09-26 全部清空，Git 里那一份现在是三本词库唯一的退路；摘掉之后库再怎么写都不会脏工作区，等于静默丢掉兜底。纳管成立的前提有四条，缺一条就要重判：`.gitattributes` 的 `binary` 命中、提交进仓库的那份 `-wal` 为 0 字节、`git pull` 前先跑漂移哨兵（`compose/tools/db-drift-sentinel.sh`）、服务器侧禁用 `git reset --hard`/`git checkout --` 覆盖库。完整口径见 `docs/项目总览.md` 的落地进度段与编排仓库 `CONVENTIONS.md` §4。
