## 4. 部署命令

### 4.1 容器方式（迁移后的标准流程）

站1 是单镜像（前端构建产物 + 后端同镜像，容器内 Express 既发页面又发 `/api/v1`），服务名 `twym`，容器名 `twym-local`。

```bash
# 本机构建并启动（在 E:\website 下执行）
docker compose up -d --build twym

# 服务器：只从 Git 拉，再重建
cd /var/www/1.my-first-website && git pull
cd /var/www && docker compose up -d --build twym

# 验证
docker compose ps twym
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api/v1/stats

# 日志 / 停止
docker compose logs --tail 50 twym
docker compose stop twym
```

三条铁律：

1. **改完代码必须带 `--build`**。Dockerfile 把 `backend/` 与前端 dist 都 COPY 进镜像，`docker compose restart` 只是重启旧镜像里的旧代码，等于没改。
2. **服务器不手改代码**，只 `git pull` + `up -d --build`；临时改动一律先落到 Git。
3. **HTTPS 由 Caddy 服务提供**，用 `.env` 里的 `COMPOSE_PROFILES=https` 开关门控，本站不需要单独跑 Caddy。

启用 HTTPS（服务器侧）：

```bash
cd /var/www                       # 根 .env 里写 COMPOSE_PROFILES=https
docker compose up -d caddy
docker compose logs caddy | grep -i "obtain\ certificate\|certificate"   # 确认证书真签发
```

### 4.2 线上旧栈：PM2（迁移前现状，亦作回滚路径）

```bash
cd /var/www/my-first-website
pm2 list                              # 查看进程状态
pm2 restart my-website --update-env   # 重启并更新环境变量（改 .env 必须带 --update-env）
pm2 logs my-website --lines 50
pm2 save && pm2 startup               # 开机自启
```

- 不要使用 `pm2 start -i max`（cluster 模式）：限流器基于内存 Map，多进程下会失效。
- 前端单独更新：本地 `cd app && npm run build`，再把 `dist/` 传到 `/var/www/my-first-website/dist/`。
- 数据库若清空需重建：`cd backend && node init-db.js` 后重启进程。
- 依赖有新增时：`cd backend && rm -rf node_modules && npm install`。

### 4.3 Nginx / 系统命令（旧栈）

```bash
nginx -t                              # 检查配置语法
systemctl reload nginx                # 热重载
tail -f /var/log/nginx/error.log      # 查看错误日志
```

### 4.4 数据库备份

`data/` 三个库都在 Git 里，SQLite 是唯一数据源。改库前先备份。

```bash
# 容器方式：三个库都在宿主机 1.my-first-website/data/ 内，直接整目录拷
cp data/同物异名.db data/backups/backup_$(date +%Y%m%d).db

# 旧栈方式
cp /var/www/my-first-website/data/同物异名.db /var/www/my-first-website/data/backups/backup_$(date +%Y%m%d).db

# 定时备份（crontab，每天凌晨 3 点）
0 3 * * * cp /var/www/my-first-website/data/同物异名.db /var/www/my-first-website/data/backups/backup_$(date +\%Y\%m\%d).db
```

> WAL 模式下，单拷 `.db` 主文件可能丢掉尚未 checkpoint 的数据；备份三站整目录（含 `-wal`/`-shm`）前先跑一次 `PRAGMA wal_checkpoint(TRUNCATE)`，或直接用 `sqlite3 库.db ".backup 目标.db"`。

## 5. Nginx 配置 (your_domain.com) —— 线上旧栈，迁移后作废

> 容器化后由 Caddy 做「域名 → 容器」整域反代，前端静态文件由各站容器自己发，下面这一堆 location 不再需要；保留仅作回滚参考。

配置文件路径：`/etc/nginx/conf.d/my-website.conf`

```nginx
server {
    listen 443 ssl;
    server_name your_domain.com www.your_domain.com;

    ssl_certificate /etc/nginx/ssl/your_domain.com.pem;
    ssl_certificate_key /etc/nginx/ssl/your_domain.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:HIGH:!aNULL:!MD5:!RC4:!DHE;
    ssl_prefer_server_ciphers on;

    # 根路径重定向到 /twym/
    location = / {
        return 302 /twym/;
    }

    # /twym 补斜杠
    location = /twym {
        return 301 /twym/;
    }

    # 前端静态文件
    location /twym/ {
        alias /var/www/my-first-website/dist/;
        index index.html;
        try_files $uri $uri/ @twym_fallback;
    }

    location @twym_fallback {
        root /var/www/my-first-website/dist;
        try_files /index.html =404;
    }

    # 后端 API 代理 (/twym/api/ → 后端 /api/)
    location /twym/api/ {
        rewrite ^/twym/api/(.*)$ /api/$1 break;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 管理后台静态 HTML
    location ~ ^/twym/admin/.*\.html$ {
        root /var/www/my-first-website/backend/public;
        rewrite ^/twym/admin/(.*)$ /$1 break;
        try_files $uri =404;
    }

    # 管理后台代理
    location /twym/admin {
        rewrite ^/twym/admin/?$ /admin break;
        rewrite ^/twym/admin/(.*)$ /admin/$1 break;
        proxy_pass http://127.0.0.1:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 直接 API 访问
    location /api/v1/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name your_domain.com www.your_domain.com;
    return 301 https://$server_name$request_uri;
}
```

## 7. 问题排查

### 7.1 本地开发问题

| 症状 | 根因 | 解决 |
|------|------|------|
| npm run dev 报错 ENOENT | 没在 app/ 文件夹执行 | `cd E:\website\1.my-first-website\app` |
| npm start 报错 ENOENT | 没在 backend/ 文件夹执行 | `cd E:\website\1.my-first-website\backend` |
| 后端 500 / 请求超时 | 后端卡住或数据库异常 | Ctrl+C 后重新 npm start |
| 页面能开但无数据 | API 超时 | Ctrl+F5 + 重启后端 |
| better-sqlite3 编译失败 | 缺 C++ 编译器或 Node 版本不对 | 装 VS Build Tools 或确认 Node v20 |
| 端口占用 EADDRINUSE | 旧进程没释放 | `taskkill /f /im node.exe` |

### 7.2 服务器问题（旧栈）

| 症状 | 根因 | 解决 |
|------|------|------|
| 网页打不开 | Nginx 没启动 | `systemctl start nginx && nginx -t` |
| 页面能开但没数据 | 后端挂了 | `pm2 list` → `pm2 restart my-website` |
| 登录失败 | .env 改了没重启 | `pm2 restart my-website --update-env` |
| 页面图片/样式丢失 | 路径没加斜杠 | 检查网址 `/twym/` |
| 502 Bad Gateway | 后端端口不匹配 | `pm2 list` + `ss -tlnp \| grep 3000` |

### 7.3 服务器问题（容器 + Caddy）

| 症状 | 根因 | 解决 |
|------|------|------|
| 改了代码没变化 | 只 restart 没 `--build` | `docker compose up -d --build twym`（镜像里烤的是旧代码） |
| `unable to prepare context` | 三站没和 compose 同级 | compose 用 `./1.my-first-website` 相对路径，必须 clone 成 `/var/www/1.my-first-website` |
| 容器 Up 但站点没数据 | bind 源不存在，Docker 静默建了个空目录 | 起来前先断言挂载源存在且非空；站1 的 `data/` 在 Git 里，`git pull` 后 `ls data/*.db` 确认 |
| 公网访问不到 3000 | 宿主端口只绑了 `127.0.0.1` | 这是有意的：公网入口走 Caddy 反代，不要改成 `0.0.0.0` |
| 域名还是 HTTP | caddy 服务被 profile 门控 | 根 `.env` 写 `COMPOSE_PROFILES=https` 后 `docker compose up -d caddy`，看 `docker compose logs caddy` 证书是否签发 |
| 容器内连不上宿主服务 | 容器里的 `localhost` 不是宿主机 | 走容器名（`twym`）或 `host.docker.internal`，别写 `localhost` |
| 图谱页面无数据 | 图数据本来就存在 SQLite（`services/知识图谱.js`），与 Neo4j 无关 | 查 `/api/v1/graph/nodes` 返回与 `data/同物异名.db` 里的图谱表是否为空 |

### 7.4 备案问题

现象："域名暂时无法访问"（阿里云备案拦截）。

原因：备案接入未完成，管局要求暂停解析。

解决步骤：
1. 登录阿里云 DNS 控制台，暂停 your_domain.com 和 www.your_domain.com 的解析记录
2. 回到阿里云备案平台，继续填写网站接入信息并提交审核
3. 等待审核：阿里云初审 1 个工作日 → 短信核验 → 管局审核 3-5 个工作日
4. 审核通过后恢复 DNS 解析

## 8. 调试铁律

1. 本地启动必须先 cd 进对应文件夹（app/ 或 backend/）
2. 改后端代码后：容器方式必须 `docker compose up -d --build`，光 restart 不生效；旧栈必须 `pm2 restart my-website --update-env`
3. Node 版本：容器用镜像里的 `node:24-slim`；只有旧栈 PM2 才受"线上必须 v20.20.2，不能回退 v22"约束
4. Windows 本地重装 node_modules 后如果 better-sqlite3 报错，确认已装 VS C++ Build Tools
5. 服务器只执行三件事：`git pull`、构建镜像、重启容器。**不在服务器上临时改代码**
6. 所有变更动手前先确认 Git 干净（`git status`），改库前先备份 `.db`
7. 改 compose / Caddyfile 前先留一份副本（这两个文件在编排仓库，改错会让三站同时受影响）
