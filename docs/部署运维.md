## 2. 目录结构

**目录结构**：compose 用相对路径 `./1.my-first-website` 引用构建上下文与挂载，所以三站必须和编排文件**同级**：

```
/var/www/                        # 编排仓库 caiminglai/website clone 在此
├── docker-compose.yml
├── caddy/Caddyfile
├── .env                         # compose 级变量，不在 Git 里，服务器上手工创建
└── 1.my-first-website/          # 站1 仓库
    ├── data/                    # 三个 .db，整目录挂到容器 /data
    └── .env                     # 只读挂到容器 /app/.env
```

数据库文件路径：容器内 `/data/同物异名.db`，宿主机 `1.my-first-website/data/`。`data/` 已在 Git 中，clone 即有数据。

## 4. 部署命令

### 4.1 标准流程（Compose + Caddy）

站1 是单镜像（前端构建产物 + 后端同镜像，容器内 Express 既发页面又发 `/api/v1`），服务名 `twym`，容器名 `twym-local`。

```bash
# 本机构建并启动（在 E:\website 下执行）
docker compose up -d --build twym

# 服务器：只从 Git 拉，再重建
cd /var/www/1.my-first-website && git pull
cd /var/www && docker compose up -d --build twym

# 验证
docker compose ps twym
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api/v1/stats

# 日志 / 停止
docker compose logs --tail 50 twym
docker compose stop twym
```

三条铁律：

1. **改完代码必须带 `--build`**。Dockerfile 把 `backend/` 与前端 dist 都 COPY 进镜像，`docker compose restart` 只是重启旧镜像里的旧代码，等于没改。
2. **服务器不手改代码**，只 `git pull` + `up -d --build`；临时改动一律先落到 Git。
3. **HTTPS 由 Caddy 服务提供**，用 `.env` 里的 `COMPOSE_PROFILES=https` 开关门控，本站不需要单独跑 Caddy。

启用 HTTPS（服务器侧）：

```bash
cd /var/www                       # 根 .env 里写 COMPOSE_PROFILES=https
docker compose up -d caddy
docker compose logs caddy | grep -i "obtain\ certificate\|certificate"   # 确认证书真签发
```

### 4.2 数据库备份

`data/` 三个库都在 Git 里，SQLite 是唯一数据源。改库前先备份。

```bash
# 三个库都在宿主机 1.my-first-website/data/ 内，直接整目录拷
cp data/同物异名.db data/backups/backup_$(date +%Y%m%d).db

# 定时备份（crontab，每天凌晨 3 点）
0 3 * * * cp /var/www/1.my-first-website/data/同物异名.db /var/www/1.my-first-website/data/backups/backup_$(date +\%Y\%m\%d).db
```

> WAL 模式下，单拷 `.db` 主文件可能丢掉尚未 checkpoint 的数据；备份三站整目录（含 `-wal`/`-shm`）前先跑一次 `PRAGMA wal_checkpoint(TRUNCATE)`，或直接用 `sqlite3 库.db ".backup 目标.db"`。

## 5. 问题排查

### 5.1 本地开发问题

| 症状 | 根因 | 解决 |
|------|------|------|
| npm run dev 报错 ENOENT | 没在 app/ 文件夹执行 | `cd E:\website\1.my-first-website\app` |
| npm start 报错 ENOENT | 没在 backend/ 文件夹执行 | `cd E:\website\1.my-first-website\backend` |
| 后端 500 / 请求超时 | 后端卡住或数据库异常 | Ctrl+C 后重新 npm start |
| 页面能开但无数据 | API 超时 | Ctrl+F5 + 重启后端 |
| better-sqlite3 编译失败 | 缺 C++ 编译器或 Node 版本不对 | 装 VS Build Tools 或确认 Node v20 |
| 端口占用 EADDRINUSE | 旧进程没释放 | `taskkill /f /im node.exe` |

### 5.2 服务器问题（容器 + Caddy）

| 症状 | 根因 | 解决 |
|------|------|------|
| 改了代码没变化 | 只 restart 没 `--build` | `docker compose up -d --build twym`（镜像里烤的是旧代码） |
| `unable to prepare context` | 三站没和 compose 同级 | compose 用 `./1.my-first-website` 相对路径，必须 clone 成 `/var/www/1.my-first-website` |
| 容器 Up 但站点没数据 | bind 源不存在，Docker 静默建了个空目录 | 起来前先断言挂载源存在且非空；站1 的 `data/` 在 Git 里，`git pull` 后 `ls data/*.db` 确认 |
| 公网访问不到 3000 | 宿主端口只绑了 `127.0.0.1` | 这是有意的：公网入口走 Caddy 反代，不要改成 `0.0.0.0` |
| 域名还是 HTTP | caddy 服务被 profile 门控 | 根 `.env` 写 `COMPOSE_PROFILES=https` 后 `docker compose up -d caddy`，看 `docker compose logs caddy` 证书是否签发 |
| 容器内连不上宿主服务 | 容器里的 `localhost` 不是宿主机 | 走容器名（`twym`）或 `host.docker.internal`，别写 `localhost` |
| 图谱页面无数据 | 图数据本来就存在 SQLite（`services/知识图谱.js`），与 Neo4j 无关 | 查 `/api/v1/graph/nodes` 返回与 `data/同物异名.db` 里的图谱表是否为空 |

### 5.3 备案问题

现象："域名暂时无法访问"（阿里云备案拦截）。

原因：备案接入未完成，管局要求暂停解析。

解决步骤：
1. 登录阿里云 DNS 控制台，暂停 your_domain.com 和 www.your_domain.com 的解析记录
2. 回到阿里云备案平台，继续填写网站接入信息并提交审核
3. 等待审核：阿里云初审 1 个工作日 → 短信核验 → 管局审核 3-5 个工作日
4. 审核通过后恢复 DNS 解析

## 6. 调试铁律

1. 本地启动必须先 cd 进对应文件夹（app/ 或 backend/）
2. 改完代码必须 `docker compose up -d --build`：代码烤在镜像里，光 `restart` 重启的还是旧镜像，等于没改。
3. Node 版本由镜像决定（`node:24-slim`），宿主机装什么 Node、glibc 什么版本都无所谓——这也是服务器换成 Debian 后不必再被版本锁坑的原因。
4. Windows 本地重装 node_modules 后如果 better-sqlite3 报错，确认已装 VS C++ Build Tools
5. 服务器只执行三件事：`git pull`、构建镜像、重启容器。**不在服务器上临时改代码**
6. 所有变更动手前先确认 Git 干净（`git status`），改库前先备份 `.db`
7. 改 compose / Caddyfile 前先留一份副本（这两个文件在编排仓库，改错会让三站同时受影响）

## 9. 本机 Docker 验证环境

本地与服务器共用根目录 `E:\website\docker-compose.yml`（服务器上是 `/var/www/docker-compose.yml`），差异只落在各自 `.env`。

| 项 | 内容 |
|:---|:---|
| 服务名 | `twym`（容器 `twym-local`） |
| 构建 | `./1.my-first-website`（Dockerfile，前端 + 后端同镜像，`node:24-slim`） |
| 端口 | 宿主 `127.0.0.1:3000` → 容器 `3000`（`/` 发前端页面，`/api/v1` 发后端 API） |
| 数据库 | SQLite：`同物异名.db`、`学科词库.db`、`语义词典.db`；挂载 `./1.my-first-website/data:/data`，**持久化** |
| 环境变量 | `./1.my-first-website/.env:/app/.env:ro` |

```bash
docker compose up -d --build twym
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:3000/              # 前端 200
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:3000/api/v1/stats  # 后端 200
```

补充说明：

- **SQLite WAL 持久化已验证合规**：`同物异名.db`、`学科词库.db`、`语义词典.db` 及各自的 `-wal`/`-shm` 全部位于 `data/` 目录内，compose 按整目录挂载 `./1.my-first-website/data:/data`，WAL 未 checkpoint 的数据不会丢，无游离 `.db` 散落在别处。
- **Neo4j 已放弃**：图数据库方向不再推进，容器编排里没有 Neo4j，生产也不依赖它；图谱读写走 SQLite（`backend/services/知识图谱.js`）。仓库里残留的 Neo4j 代码与 `npm run sync:neo4j` 属历史包袱，清理待办记在 IDE 任务列表（#6 依赖清理、#34 中文路由参数）。
- **Meilisearch 未启用**：`backend/bin/meilisearch.exe` 与启动脚本已删除，编排里也没有它。`backend/services/Meilisearch服务.js` 探测不到服务时自动回退，搜索实际走 SQLite `LIKE` 查询，无需任何外部服务。现状细节见 `项目总览.md`「数据库现状」。
