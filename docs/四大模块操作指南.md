# 同物异名 · Obsidian 内容协作方案

> **目标**: 网站数据库作为唯一真相源,Obsidian 作为可读可批注的内容副本。
> **支持模块**: 词条、概念对比
> **说明**: 职业解构/岗位拆解/概念抗体 因涉及多表关联,建议通过管理后台编辑
> **同步方向（重要）**: **只有「数据库 → Obsidian」单向导出**。`backend/services/Obsidian同步.js` 全部是写出函数（`writeTermToObsidian`、`syncAllTerms`、`fullSync` 等),仓库里**没有任何把 Markdown 解析回数据库的代码**。因此在 Obsidian 里改文字不会自动进库,必须回到管理后台改数据,再由后端重新导出覆盖。
> **更新日期**: 2026-09-20（按代码实测校正同步方向）

---

## 一、工作流程（实测方向）

```
管理后台/API 写入 SQLite（唯一真相源）
         ↓
  保存时实时导出：routes/管理.js、routes/概念对比.js 调用 write*ToObsidian
         ↓
  全量补齐：POST /api/v1/admin/sync-obsidian（需 x-admin-token）→ fullSync()
         ↓
  Obsidian 仓库（obsidian/ 目录）得到最新 Markdown
         ↓
   网站 API 实时展示（读的也是 SQLite）
```

> 反向链路（在 Obsidian 编辑 → 解析入库）**未实现**。想要多人协作编辑内容,当前只能：社区用户提交 → `词条纠错建议` 表 → 管理员审核后在管理后台落库。

## 二、Obsidian 仓库结构

实测 `obsidian/` 目录（由后端导出，不是手工建的）：

```
obsidian/
├── 词条/              ← 按学科分子目录，目录名必须与 学科 表一致
│   ├── 数学/  物理学/  化学/  生物学/
│   ├── 计算机/  经济学/  法律政策/
│   └── 医学心理/  控制论/  跨学科/
├── 概念对比/          ← 文件名即 "概念A vs 概念B"
└── 岗位拆解/          ← fullSync 的 syncAllJobs 按 分类名称 分子目录导出
```

> 没有 `模板/` 目录：第三节给出的格式是**导出文件实际长什么样**的说明，可直接当作录入模板抄。
> `概念抗体` 也在 `fullSync` 的模块清单里，但 概念抗体 表当前 0 行，所以没有导出目录。

> 注意：`概念抗体/`、`职业解构/`、`岗位拆解/` 这三个模块不支持 Obsidian 写入（本来就只有导出方向），如需编辑请通过管理后台 http://localhost:3000/admin 。

## 三、模板使用说明

### 模板1：词条（核心模块）

**文件存放位置**: `词条/学科名/词条名称.md`

**frontmatter 字段说明**（必须严格按此格式）：

```yaml
---
类型: 词条
词条ID: econ-001          # 唯一ID，不填则自动生成
学科: 经济学               # 必须是已有学科
热度: 1                    # 可选，默认0
创建时间: 2026-06-24      # 可选，自动生成
别名: ["边际效应", "Marginal Utility"]  # 跨学科别名，JSON数组
---
```

**正文格式**（使用以下标题标记）：

```markdown
# 词条名称（一级标题 = 名称）

**专业说法：** 每增加一单位消费所带来的额外满足程度。

**人话翻译：**
就像你吃包子。饿的时候第一个包子香得很，第二个还行...

**本质：** 增量满足递减规律

**提示：** 别被"边际"两个字唬住

**跨学科别名：**   ← 下面写 [[双链]] 格式
- [[饱和效应]]
- [[机会成本]]

**相关术语：**      ← 下面写 [[双链]] 格式
- [[沉没成本]]
```

**重要规则**:
- `学科` 必须是 `学科` 表里已有的值，实测共 10 个：数学、物理学、化学、生物学、跨学科、计算机、经济学、法律政策、医学心理、控制论（**没有**"医学""心理学""计算机科学"这类写法）
- 文件名即为词条名称，`名称` 字段可省略
- `[[词条名称]]` 双链是**导出结果**：`writeTermToObsidian` 从 图谱关系 表读出关联词条再拼成双链；在 Markdown 里手写双链不会反向入库

### 模板2：概念对比

**文件存放位置**: `概念对比/对比标题.md`

**frontmatter 字段说明**：

```yaml
---
类型: 概念对比
对比ID: cmp-001          # 唯一ID，不填则自动生成
关系类型: 关联性          # 可选：同义词/反义词/包含关系/相近概念/关联性
创建时间: 2026-06-24      # 可选，自动生成
---
```

**正文格式**：

```markdown
# 概念A名称 vs 概念B名称

## 概念A：边际效用

**所属学科：** 经济学

**人话翻译：** 再多吃一个包子的爽感

**表现症状：** 越买越不划算

**生活类比：** 吃包子

**解决办法：** 适可而止

## 概念B：沉没成本

**所属学科：** 经济学

**人话翻译：** 已经花出去的钱

**表现症状：** 舍不得放弃

**生活类比：** 电影票买了不好看也看完

**解决办法：** 及时止损

## 总结

**一句话区分：** 边际效用是未来还能爽多少，沉没成本是过去已经花掉的钱。
```

**重要规则**:
- 标题必须包含 `vs`（大小写均可），用于自动拆分两个概念
- `所属学科` 必须和数据库里的学科名称一致

## 四、Git 同步（现状：Obsidian 目录就在代码仓库里）

实测：`obsidian/` 是**站1 仓库内被 Git 跟踪的普通目录**（`git ls-files` 能看到 `obsidian/词条/经济学/边际效用.md` 等）。
仓库里**没有** post-receive 钩子、**没有**服务端自动同步脚本、也**没有**把 Markdown 解析回数据库的代码 ——
所以"push 到裸库后服务器自动入库"这条链路目前不存在，别按它安排工作。

### 4.1 现状做法（导出方向）

```bash
# 1) 触发全量导出（需 x-admin-token；本地默认 http://localhost:3000）
curl -X POST http://localhost:3000/api/v1/admin/sync-obsidian \
  -H "x-admin-token: 你的ADMIN_TOKEN" -H "Content-Type: application/json" -d '{}'

# 2) 用 Obsidian 打开仓库内的 obsidian/ 目录查看/批注
# 3) 导出结果与代码一起提交
git add obsidian && git commit -m "chore(obsidian): 同步导出" && git push
```

日常增量不用手动触发：管理后台保存/删除词条与概念对比时，`routes/管理.js`、`routes/概念对比.js` 会同步调用 `write*ToObsidian` / `delete*FromObsidian` 立刻改写对应 md 文件。

### 4.2 想要"社区成员只改 Markdown 就能进库"？

那是**反向入库**（MD → SQLite），当前未实现，需要新开发一个解析脚本 + 审核入表逻辑，再挂到管理后台。在此之前，社区协作的通路是：网站提交 → `词条纠错建议` 表 → 管理员在后台改库。

## 五、文件清单（实测存在，2026-09-20）

| 文件 | 用途 |
|------|------|
| `obsidian/` | Obsidian 内容目录（就在站1 仓库内，被 Git 跟踪） |
| `backend/services/Obsidian同步.js` | **数据库 → Obsidian 导出**：`fullSync` 全量、`write*ToObsidian` 单条写入、`delete*FromObsidian` 删除、`syncAll*` 批量 |
| `backend/routes/管理.js` | 管理后台路由，`:494` `POST /sync-obsidian` 是全量导出的 HTTP 入口 |
| `backend/services/Meilisearch服务.js` | **已废弃**：探测不到 Meilisearch 时自动回退，搜索实际走 SQLite `LIKE`；无外部服务，也无同步脚本 |

> 历史文档里提到的 `模板/词条.md`、`模板/概念对比.md`、`scripts/数据库同步到Obsidian.js`、`scripts/数据库备份.js`、`scripts/启动服务.bat`、`scripts/端口清理.bat`、`scripts/同步到Meilisearch.js` 均已不存在（仓库根**没有** `模板/` 与 `scripts/` 目录），别按它们操作。
> 数据库备份是手工 `cp`/`sqlite3 .backup`，见 `docs/部署运维.md` 第 4.4 节。
